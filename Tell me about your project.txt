One-to-One
One-to-Many
Many-to-Many

The overall flow was:

Reading/importing transaction files
Validating transaction data
Applying reconciliation rules
Updating transaction status, flags, and remarks in database.

-> One major challenge was processing large transaction files efficiently.

To optimize this, I used STL containers like map for faster lookup and improved processing logic, which reduced execution time and improved performance.

Another challenge was memory leaks in the application.
Some dynamically allocated memory was not being released properly, causing higher memory usage during large file processing.
I analyzed the issue using debugging and monitoring, fixed improper memory handling, and ensured proper cleanup to stabilize the application.
